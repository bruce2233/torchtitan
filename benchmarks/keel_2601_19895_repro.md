# KEEL Reproduction Configs

This branch adds TorchTitan configs for reproducing the KEEL architecture from
arXiv:2601.19895v2, "Post-LayerNorm Is Back: Stable, ExpressivE, and Deep".

## Architecture Mapping

The KEEL sub-layer is implemented as:

```text
x_next = RMSNorm(alpha * x + F(RMSNorm(x)))
```

where `alpha` is the total number of residual sub-layers. A TorchTitan
Transformer block has two residual sub-layers, attention and FFN, so the
paper's 512-layer setting maps to 256 TorchTitan blocks and `alpha=512`.

The paper's input-layer initialization rule is also reflected:

- the first attention sub-layer uses no PostNorm
- the first attention and first FFN sub-layers use `alpha=1`
- all RMSNorms have learnable affine weights and no bias

## Model Flavors

The new Llama3 model flavors are:

- `keel_debugmodel`
- `keel_64x1024`, `keel_256x1024`, `keel_512x1024`, `keel_1024x1024`
- `preln_64x1024`, `preln_256x1024`, `preln_512x1024`, `preln_1024x1024`

The paper-scale model configuration uses `d_model=1024`, FFN intermediate
dimension `3072`, 16 attention heads, 8 KV heads, RMSNorm epsilon `1e-5`,
RoPE theta `10000`, and normal initialization with standard deviation `0.02`.

## Training Configs

The runnable config-registry entries are:

- `llama3_keel_debugmodel`: local smoke config
- `llama3_keel_512x1024_1t`: KEEL 512-sub-layer paper-scale config
- `llama3_preln_512x1024_1t`: Pre-LN 512-sub-layer baseline config

Paper-scale configs use AdamW with `beta1=0.9`, `beta2=0.95`, weight decay
`0.01`, sequence length `4096`, global batch size `2048`, 2500 warmup steps,
and cosine decay to `1e-7`. KEEL uses peak LR `4.5e-3`; Pre-LN uses
`3.0e-3`.

The original paper trains on an internal 1T-token corpus with a 750B-token
general pre-training phase followed by 250B-token continued pre-training.
These configs default to public C4 so they are executable in TorchTitan; pass
`--dataloader.dataset` or `--dataloader.dataset_path` overrides for a matching
local corpus.

## Launch Training

The helper script maps `MODE` to the TorchTitan config-registry entry and
forwards any remaining CLI arguments to `run_train.sh`.

```bash
./scripts/run_keel_repro.sh --help
```

### Smoke Test

Use the local `c4_test` fixture to verify config parsing, model construction,
forward/backward, and checkpoint plumbing. This mode forces `--training.steps 3`.

```bash
MODE=smoke NGPU=1 ./scripts/run_keel_repro.sh
```

For a distributed-shape dry run without launching all ranks, use
`COMM_MODE=fake_backend`; `run_train.sh` will build the requested parallel
configuration and execute one training step through the fake process-group path.

```bash
COMM_MODE=fake_backend MODE=keel_512x1024_1t NGPU=64 \
  ./scripts/run_keel_repro.sh \
  --parallelism.pipeline_parallel_degree 8 \
  --parallelism.tensor_parallel_degree 1
```

### Dataset And Tokenizer

Paper-scale configs use the Llama 3.1 tokenizer path
`./assets/hf/Llama-3.1-8B`. Download tokenizer assets before the first run:

```bash
python scripts/download_hf_assets.py \
  --repo_id meta-llama/Llama-3.1-8B \
  --assets tokenizer \
  --hf_token "${HF_TOKEN}"
```

The default dataset is public C4. To use a local corpus or a different supported
loader, append normal TorchTitan dataloader overrides:

```bash
--dataloader.dataset fineweb_edu \
--dataloader.dataset_path '/data/fineweb_edu/*.parquet'
```

Set `HF_DATASETS_CACHE` to a shared fast filesystem on clusters so every rank
does not redownload dataset shards into node-local storage.

### Single-Node Launch

This starts the paper-scale KEEL config on one node. With `NGPU=8`, the config
keeps `global_batch_size=2048` and uses gradient accumulation to make up the
remaining global batch.

```bash
HF_DATASETS_CACHE=/data/cache/hf_datasets \
MODE=keel_512x1024_1t \
NGPU=8 \
LOG_RANK=0 \
./scripts/run_keel_repro.sh \
  --dataloader.dataset fineweb_edu \
  --dataloader.dataset_path '/data/fineweb_edu/*.parquet' \
  --dump_folder ./outputs/keel_512x1024_1t_single_node
```

Run the Pre-LN baseline by switching only `MODE`:

```bash
HF_DATASETS_CACHE=/data/cache/hf_datasets \
MODE=preln_512x1024_1t \
NGPU=8 \
LOG_RANK=0 \
./scripts/run_keel_repro.sh \
  --dataloader.dataset fineweb_edu \
  --dataloader.dataset_path '/data/fineweb_edu/*.parquet' \
  --dump_folder ./outputs/preln_512x1024_1t_single_node
```

### Multi-Node Slurm Launch

For the 64-GPU example below, use 8 nodes with 8 GPUs each and pass
`pipeline_parallel_degree=8`; the remaining ranks are used by FSDP because
`data_parallel_shard_degree=-1` by default. Save this as a job script or adapt
the repository's `multinode_trainer.slurm` with the same `CONFIG`, node count,
and `torchrun --nnodes` values.

```bash
#!/bin/bash
#SBATCH --job-name=keel-512x1024
#SBATCH --nodes=8
#SBATCH --ntasks=8
#SBATCH --gpus-per-task=8
#SBATCH --cpus-per-task=96
#SBATCH --partition=train

set -euo pipefail

nodes=( $(scontrol show hostnames "${SLURM_JOB_NODELIST}") )
head_node="${nodes[0]}"
head_node_ip="$(srun --nodes=1 --ntasks=1 -w "${head_node}" hostname --ip-address)"

export LOGLEVEL=INFO
export LOG_RANK=0
export HF_DATASETS_CACHE=/data/cache/hf_datasets
export PYTORCH_ALLOC_CONF=expandable_segments:True

srun torchrun \
  --nnodes "${SLURM_NNODES}" \
  --nproc_per_node 8 \
  --rdzv_id "${SLURM_JOB_ID}" \
  --rdzv_backend c10d \
  --rdzv_endpoint "${head_node_ip}:29500" \
  --local-ranks-filter "${LOG_RANK}" \
  --role rank \
  --tee 3 \
  -m torchtitan.train \
  --module llama3 \
  --config llama3_keel_512x1024_1t \
  --parallelism.pipeline_parallel_degree 8 \
  --dataloader.dataset fineweb_edu \
  --dataloader.dataset_path '/data/fineweb_edu/*.parquet' \
  --dump_folder ./outputs/keel_512x1024_1t_slurm
```

For the Pre-LN baseline, change `--config` to
`llama3_preln_512x1024_1t` and use a separate `--dump_folder`.
